## Blockers

### 1. `setup-vibe.sh` fails when `~/.vibe/agents` is a real directory

`scripts/setup-vibe.sh:100-104`

```bash
elif [ -e "$link" ]; then
  cp -a "$link" "$link.bak"
  rm -f "$link"
```

`rm -f` cannot remove a directory, and `set -e` aborts. Reproduced in a sandbox with a pre-existing `~/.vibe/agents` directory: `config.toml` was linked, `agents.bak` was created, then the script exited 1 with `rm: cannot remove '.../agents': Is a directory`, leaving `~/.vibe/agents` unlinked and `~/.vibe/.env` never linked.

Likely on the laptop if Vibe has been run there before. Fix by moving the existing entry aside (`mv`), or handling directories explicitly, and handle an existing `agents.bak` without nesting. A re-run after this failure will also nest `agents` inside `agents.bak`.

### 2. `$SECRETS_DIR` is never created

`scripts/setup-vibe.sh:31-36`

On a device without `/opt/secrets`, `: > "$ENV_FILE"` fails with `No such file or directory` and the script exits 1 before creating any symlinks. Reproduced in a sandbox. Add `mkdir -p -m 700 "$SECRETS_DIR"` before creating the env file.

### 3. A new device cannot populate its own secrets

`scripts/setup-vibe.sh:41-81`, `vibe/README.md:74-83`

The script only copies key files that already exist locally (`github.token`, `trilium.token`, `litellm.key`, `engram-cloud.token`, `comfyui-mcp.url`). On a laptop without those files it warns and continues, producing a partial `vibe.env`; only the missing Mistral key is called out specially. The README does not say how to get the key files or `/opt/secrets` onto the new device.

Choose one:
- document a copy step from the server (for example `scp` of the relevant `/opt/secrets` entries) and a final `/mcp` check; or
- make missing required sources fatal so the bootstrap does not finish half-configured.

Also: `OPENAI_API_KEY` is not seeded although `gpt-6.1-sol` and `gpt-6-luna` are declared in `config.toml`.

## Env routing: what is necessary

Verified against the installed Vibe 3.1.3 source and the running commands:

| Mechanism | Necessary? | Evidence |
|---|---|---|
| `~/.vibe/.env` -> `/opt/secrets/vibe.env` | **Yes** | Vibe loads only `$VIBE_HOME/.env`; a non-empty shell value wins over the file. Keeps secrets out of git. |
| Wrappers around `trilium`, `engram`, `comfyui` | **Yes** | Stdio MCP children receive only `HOME, LOGNAME, PATH, SHELL, TERM, USER` (`mcp/client/stdio.py`); secrets must be injected by the wrapper. |
| `COMFYUI_MCP_URL` + `mcp-remote` bridge | **Yes** | Vibe does not expand env vars in an MCP `url`; putting the tailnet URL in `config.toml` would commit it. |
| `github` via `api_key_env = "GITHUB_TOKEN"` | **Correct, no wrapper needed** | HTTP MCP static auth resolves `os.getenv()` in Vibe's process, which has loaded `.env`. |
| Separate `vibe.env` from `mistral.env` | **Not functionally required** | Both `MISTRAL_API_KEY` values authenticate against `api.mistral.ai` (verified with `/v1/models` and a 1-token chat completion; values were not printed). The split is justified only by quota/rotation isolation. |
| `export HOME="${HOME:-$(getent ...)}"` in wrappers | **Unnecessary** | `HOME` is already in the curated child env. Harmless, but dead code. |
| `unset MISTRAL_API_KEY` in the deep-research wrapper | **Unnecessary** | The child does not inherit it. The `MISTRAL_API_KEY_FILE` pin is the part that matters. |
| Sourcing the whole `.env` into every stdio child | **Over-broad** | Gives Trilium, Engram, and ComfyUI the Mistral quota key, GitHub token, and LiteLLM key. Works, but least privilege would export only the needed variable. |

If the two-key separation is kept, clean up `mistral.env`: it still contains the six keys appended by the first version of `setup-vibe.sh`. `litellm/compose.yml` loads that file, so the LiteLLM container receives GitHub, Trilium, Engram, and ComfyUI secrets it does not use. This is a security/cleanup issue and a rotation-drift risk.

## Config and setup cleanliness

- **Hardcoded username:** `vibe/config.toml:140,161,167` deny `/home/johannes/.ssh/*`. Denylist matching does not expand `~`, so if the laptop username differs, `~/.ssh` is not protected. Use `*/.ssh/*` or document the identical-username assumption.
- **Hardcoded `uvx`:** `vibe/config.toml:242` uses `/home/johannes/.local/bin/uvx`. Prefer `uvx` from `PATH`; the MCP SDK already passes `PATH`.
- **Hardcoded repo root:** `/opt/stacks` appears in `skill_paths` (`config.toml:6-8`), the deep-research script (`:260`), and the Playwright mounts (`:227-229`), while `setup-vibe.sh` supports `STACKS_DIR`. Either require `/opt/stacks` everywhere and drop the override, or generate those paths.
- **LAN-only endpoints:** LiteLLM (`config.toml:68`) and Trilium (`:212`) use `192.168.0.46`; ComfyUI is already tailnet-routed. At home this works; away from home those MCPs/models fail. Route them via tailnet/env if the laptop moves.
- **OpenAI models without a key:** `config.toml:36-44,71-74` declares `gpt-6.1-sol` / `gpt-6-luna`, but no `OPENAI_API_KEY` is provisioned. Selecting them will fail at auth. Seed the key or remove the models/provider.
- **Vision agent cannot read images:** `vibe/agents/vision.toml:4-5,14` claims `read_file` reads images. Vibe 3.1.3's `read_file` is line-based text only (verified in `vibe/core/tools/builtins/read_file.py`). The subagent cannot do its job as configured.
- **Review skill is OpenCode-specific:** `.opencode/skills/review/SKILL.md:3,26-39` says to launch the shared Auto reviewer through the session-model selector, which does not exist in Vibe. The lowercased skill loads, but the instruction is misleading. Consider `disabled_skills = ["review"]` for Vibe or a Vibe-specific variant.
- **Misleading validation advice:** `vibe/README.md:88` says validate with `vibe config schema`. That only prints the schema; a config with an unknown key still returns rc=0. Use `strict_config = true` / `VIBE_STRICT_CONFIG=1` at startup instead.
- **Linux-only shell assumptions:** `readlink -f` (`setup-vibe.sh:93`) is not available in BSD/macOS `readlink`; `getent` in the wrappers is Linux-only (though it is only reached if `HOME` is unset). Fine on Linux, a problem if the laptop is macOS.
- **Token refresh:** `add()` skips keys that already exist, so rotated tokens are not refreshed. The README documents manual rotation, but the script looks like it synchronizes. State that `vibe.env` is authoritative after first run, or add a refresh mode.
- **Backup handling:** `link()` overwrites an existing `.bak` and can nest backups on repeated failures. Use a non-clobbering backup.
